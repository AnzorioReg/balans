# Валидация Баланс

## Цель
Проверка целостности и корректности работы приложения после переноса исходников.

## Что проверять

### Структура проекта
- [ ] Наличие `app/`, `web-src/`, `gradle/`, `gradle/wrapper/`
- [ ] `app/build.gradle`, `AndroidManifest.xml`, `assets/index.html`
- [ ] `web-src/src.html`, `web-src/build.py`
- [ ] Ключевые JS-модули и QA-скрипты

### Сборка
- [ ] `./gradlew assembleDebug` проходит без ошибок
- [ ] APK содержит актуальный `index.html` из assets

### Функциональность
- [ ] Главный экран открывается
- [ ] Наборы визуализаций переключаются
- [ ] Health Connect запрос разрешений работает
- [ ] BLE-сканирование и подключение (на поддерживаемых устройствах)
- [ ] Напоминания создаются и срабатывают
- [ ] Настройки внешности и идентичности сохраняются

### Регрессия
- [ ] Набор «Авторские» соответствует исходным viz.js / viz2.js
- [ ] Нет потери данных измерений
- [ ] Приоритет источников данных соблюдается

## QA-скрипты в web-src

В папке `web-src/` находятся скрипты проверки:
- `qa-functional113.js`
- `qa-ui114.js`, `qa-ui114-hero.js`
- `qa-records114.js`, `qa-settings114.js`
- `qa-realvisual114.js`, `qa-metric-designs114.js`
- `qa-author115.js`, `qa-original-author115.js`
- `qa-goal116.js`, `qa-analysis116.js`
- `qa-performance.js`

Запускать в контексте собранного `index.html` или через build.py.

## Известные ограничения
- Полная проверка BLE и Health Connect требует физического устройства.
- Некоторые QA-скрипты рассчитаны на конкретные версии визуализаций.
